📚 一、RAG 原理回顾

先明确要实现的流程图，再动手写代码

RAG 是构建知识库和智能客服的首选方案，整体流程分成两个部分：

  • 准备部分（用户提问前）：分片 + 索引
  • 回答部分（用户提问后）：召回 + 重排 + 生成
🎬 00:25 · 本视频第一节：RAG 的整体流程

🔧 准备部分（提问前）

把相关资料做分片，然后把所有片段都扔给 Embedding 模型，让它给每个片段都产出一个对应的向量， 最后把向量存入向量数据库。到这一步，知识库就构建完毕，等用户来用。

🎬 00:55 · 产品使用手册 → 片段列表 → Embedding 模型 → 向量 → 向量数据库

💬 回答部分（提问后）

用户的问题先给到 Embedding 模型转换为向量，再把这个向量传给向量数据库， 让它找出最相似的若干片段；接着把片段送给 CrossEncoder 模型做重排，选出相关度最高的几个； 最后把筛选后的片段外加用户问题一起发给大模型，产出最终答案。

🎬 01:20 · 用户提问 → Embedding → 向量库召回 → 重排 → 大模型生成
💡 本期视频的定位 原理部分只是快速带过，重点是用 Python 把上面这张图真正实现出来。 为了验证检索准确性，作者特意准备了一篇「谁也不可能看过」的文章作为知识库内容。

✂️ 四、写代码 1：分片

把长文档切成片段列表

RAG 系统的第一步就是分片。先导入 List 对象用于标注函数返回结果的类型， 然后创建一个函数用来处理分片的逻辑，函数名就叫 split_into_chunks（chunk 就是片段的意思）。

from typing import List

def split_into_chunks(doc_file: str) -> List[str]:
    with open(doc_file, 'r') as file:
        content = file.read()
    return [chunk for chunk in content.split("\n\n")]

chunks = split_into_chunks("doc.md")
🎬 06:10 · split_into_chunks 函数与调用

函数说明：

  • 参数 doc_file：文档名，调用时把 doc.md 传进来
  • 返回值：一个字符串列表，也就是分好的片段列表
  • 内部逻辑：先读取文件内容放到 content 变量，然后按空行（\n\n）来拆分

调用这个函数并循环遍历拿到所有片段，把片段的编号和内容都打印出来，验证结果是否符合预期。

🔢 五、写代码 2：索引

片段转向量，再存进向量数据库

1️⃣ 加载 Embedding 模型

先引入 SentenceTransformer，然后用它加载一个 Embedding 模型。

🎬 06:45 · 加载 shibing624/text2vec-base-chinese 模型
from sentence_transformers import SentenceTransformer

embedding_model = SentenceTransformer("shibing624/text2vec-base-chinese")

之后写一个函数 embed_chunk，用来获取某个给定片段对应的向量。 其中的 chunk 参数就是片段的内容，返回的数字列表就是对应的向量。

def embed_chunk(chunk: str) -> List[float]:
    embedding = embedding_model.encode(chunk)
    return embedding.tolist()

# 测试：确认向量维度
test_embedding = embed_chunk("测试内容")
print(len(test_embedding))
print(test_embedding)

3️⃣ 存入向量数据库 ChromaDB

向量值求出来了，接下来就需要把这些向量存入到向量数据库中。这里选用的向量数据库是 ChromaDB。

🎬 09:20 · EphemeralClient（内存）与 PersistentClient（落盘）
import chromadb

chromadb_client = chromadb.EphemeralClient()

🧠 EphemeralClient

  • 创建内存型向量数据库
  • 数据不会写入磁盘
  • 脚本运行结束后自动清除数据
  • 本视频选用的方式

💾 PersistentClient

  • 数据持久化到磁盘
  • 后面直接指定具体的文件名
  • 示例：chromadb.PersistentClient("./chroma.db")
  • 数据存放在 chroma.db 文件中

Collection 是 ChromaDB 的概念，可以把它理解为传统数据库里面的表格。

接着写一个函数，把所有的片段内容和对应的向量都存到这个数据库中：

🎬 10:20 · save_embeddings：生成 ids 并调用 collection.add
def save_embeddings(chunks: List[str], embeddings: List[List[float]]) -> None:
    ids = [str(i) for i in range(len(chunks))]
    chromadb_collection.add(
        documents=chunks,
        embeddings=embeddings,
        ids=ids
    )

save_embeddings(chunks, embeddings)

这个函数有两个参数，其中 chunks 是片段内容列表，embeddings 就是对应的片段向量列表，它们的长度都是 10。

在函数内部，首先要生成一个 ids 变量，它的值就是从 0 到 9 的一个字符串列表。 因为 ChromaDB 要求每一个记录都要有一个 ID，所以需要定义这个变量，它就代表了每个记录的 ID。 定义好 IDs 之后，把所有的片段内容、所有的片段向量和所有的片段编号一起传给 ChromaDB。

⚠️ 出现的报错可以忽略 执行后会输出几条 Failed to send telemetry event ... capture() takes 1 positional argument but 3 were given 错误信息。 这是 ChromaDB 与其他依赖版本没对齐导致的，不影响正常使用，测试时这个问题大概率已经被修复掉了。

🎣 六、写代码 3：召回

用向量相似度捞出候选片段

下面处理用户提问之后所发生的事情，分别是召回、重排和生成。

首先定义一个函数叫做 retrieve，专门用作召回：

def retrieve(query: str, top_k: int) -> List[str]:
    query_embedding = embed_chunk(query)
    results = chromadb_collection.query(
        query_embeddings=[query_embedding],
        n_results=top_k
    )
    return results['documents'][0]
🎬 11:40 · retrieve 函数：问题转向量，再查向量库

函数说明：

  • 两个参数：用户的问题 query，以及最终要召回的记录数量 top_k
  • 返回值：一个列表，代表召回的片段内容，列表大小跟 top_k 相同
  • 内部逻辑：先调用 embed_chunk 把用户的问题转换成向量， 然后把这个向量传入 ChromaDB，查询与用户问题最为相似的前 top_k 个结果，再返回片段列表

🧪 测试召回

输入问题：「哆啦A梦使用的三个秘密道具分别是什么」，然后调用 retrieve 获取与这个问题最为相关的 5 个片段并打印出来。

query = "哆啦A梦使用的三个秘密道具分别是什么"

🔀 七、写代码 4：重排

用 CrossEncoder 重新打分排序

重排阶段需要的模型是 CrossEncoder，所以先引入 sentence_transformers 的 CrossEncoder 包， 然后写重排函数 rerank。

from sentence_transformers import CrossEncoder

def rerank(query: str, retrieved_chunks: List[str], top_k: int) -> List[str]:
    cross_encoder = CrossEncoder('cross-encoder/mmarco-mMiniLMv2-L12-H384-v1')
    pairs = [(query, chunk) for chunk in retrieved_chunks]
    scores = cross_encoder.predict(pairs)

    chunk_with_score_list = [(chunk, score)
                             for chunk, score in zip(retrieved_chunks, scores)]
    chunk_with_score_list.sort(key=lambda pair: pair[1], reverse=True)

    return [chunk for chunk, _ in chunk_with_score_list][:top_k]

这个函数一共有三个参数：

  1. 用户的问题 query
  2. 召回的片段列表 retrieved_chunks
  3. 重排后保留的片段数量 top_k

函数返回一个列表，就是重排后保留的片段列表，top_k 有多大，这个列表里面就有多少个元素。

在函数内部，首先创建一个 CrossEncoder 模型，然后创建一个列表，这个列表里面的每一个元素都是 「用户问题 + 一个召回的片段」组成的 pair，然后把这个列表发给 CrossEncoder 模型， 让它给每一个片段打分，分值就代表了用户问题与对应片段内容的相似程度。

🎬 14:00 · 片段与分数组成列表，再按分数倒序排序

得到的分数大概是这样：

chunk_with_score_list = [
    (召回片段2, 10.001404),
    (召回片段3, -2.1272113),
    (召回片段1, -3.389875),
    (召回片段5, -4.7948947),
    (召回片段4, -5.354384),
]

然后把召回的片段和分数放在一起做成一个列表，之后把这个列表按分数倒序排序。 这样做之后，列表里面的第一个元素就是与用户问题最为相关的片段加上对应的匹配分数，第二个元素、第三个以此类推。

拿到这个列表之后，再单独取出其中的片段内容部分，把分数扔掉，然后再取前 top_k 个结果，这就是我们的答案了。

🧪 测试重排

for i, chunk in enumerate(reranked_chunks):
    print(f"[{i}] {chunk}\n")
🎬 14:45 · 重排后，包含答案的片段排到了第 [0] 位
✅ 重排生效了 可以看到，重排后包含答案的这个片段排到了第一名的位置。由此可以看出， 重排的效果确实要比 Embedding 好很多 —— 重排阶段所使用的 CrossEncoder 模型， 可以非常准确地识别哪些片段与用户问题最为相关。
💡 为什么重排更准 Embedding 是把问题和片段分别编码成向量再算距离，两者从未「见过面」； 而 CrossEncoder 是把「问题 + 片段」拼在一起同时送进模型， 能直接建模两者的交互关系，所以打分更准。代价是它必须对每个候选片段单独跑一次前向计算， 因此只能用在召回之后的少量候选上。

3️⃣ 写 generate 函数

做好必要的准备之后，就可以写 generate 函数了。这个函数有两个参数， 分别是用户问题 query 和重排后得到的片段列表 chunks，它会返回最终的答案。

🎬 16:45 · 组装 prompt，调用 gemini-2.5-flash
def generate(query: str, chunks: List[str]) -> str:
    prompt = f"""你是一位知识助手，请根据用户的问题和下列片段生成准确的回答。

用户问题：{query}

相关片段：
{"\n\n".join(chunks)}

请基于上述内容作答，不要编造信息。"""

    print(f"{prompt}\n\n---\n")

    response = google_client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt
    )
    return response.text

在函数内部，首先写好要送给大模型的 prompt —— 用户的问题写在这里，相关的片段写在这里， 然后我们把 prompt 打印出来看一下。之后调用 Gemini 2.5 Flash 模型，把提示词送给它，让它生成最终的答案，最后将答案返回。

chunks = split_into_chunks("doc.md")                 # 1. 分片
embeddings = [embed_chunk(c) for c in chunks]        # 2. 向量化
save_embeddings(chunks, embeddings)                  # 3. 存入向量库

# ---------- 回答部分（提问后，每次提问都跑） ----------
query = "哆啦A梦使用的三个秘密道具分别是什么"
retrieved_chunks = retrieve(query, 5)                # 4. 召回 top-5
reranked_chunks = rerank(query, retrieved_chunks, 3) # 5. 重排 top-3
answer = generate(query, reranked_chunks)            # 6. 生成答案
print(answer)
