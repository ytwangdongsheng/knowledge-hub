🔢 一、Token：大模型为什么不直接读文字

Token 就是一个一个代表字词的编号

1）提高效率：计算机里文字是离散的字符

和大模型聊天的时候，我们都是直接输入文字的。但实际上现在基本所有的 LLM，都要先通过一个叫做 Tokenizer 的东西，把文字转化成 token。

所谓 token，其实就是一个一个代表字词的编号。那为什么要进行这一步呢？直接处理文字不好吗？

⚠️ 原因很简单：为了提高效率 在电脑之中，文字都是一个字符一个字符存储的。比如说 Apple，计算机存储的并不是 "Apple" 这个词，而是 A、p、p、l、e 五个离散的字母。如果用离散的字母来训练模型，那就先要求模型从这五个字母中识别出"它是苹果"，然后再用"苹果"这个概念进行下一步处理。

不是说不行，但在算力有限的情况下，这样做效率太低了。
📷 完整链路：用户输入"老王爱吃苹果" → tokenizer → 数字 7 15 3 871 → 大语言模型

所以人们就给大模型做了一个词表（词典），用数字来代表单词。比如数字 1 代表 Apple，数字 2 代表 Banana，数字 3 代表 Pear。而 1、2、3 这些数字，就是所谓的 token。

📷 数字 1 就代表 Apple，数字 2 就代表 Banana

2）Token 与单词不是严格一一对应

当然，token 和单词也不是一一严格对应的。有时候一个单词可能会被拆分成多个 token。

比如说 oldest 这个单词，就可能被拆分成一个代表 old 的 token，和一个代表最高级 est 的 token。这样做的好处是，可以帮助大模型认识一些没有见过的词。

✅ 举例：Goodest Goodest 这个词本身是不存在的，但是却可以被拆解成 good 和 est，大模型也就理解了。
📷 oldest = 4 (old) + 5 (est)：一个词拆成两个 token

这样一来，大模型处理的就不是单独的字母了，而是 1、2、3 这些代表某些单词或者单词片段的数字，于是效率就高多了。

而这些把文字转化成数字、又把数字转化回文字的程序，就叫做 Tokenizer。

3）常见的 Tokenizer 与算法

现在比较常见的 Tokenizer 库，有 OpenAI 的 tiktoken 和谷歌的 WordPiece 等等。这些 Tokenizer 的内部实现原理不尽相同：

Tokenizer使用算法共同功能
tiktoken（OpenAI）BPE把字词转化成数字
WordPiece（Google）WordPiece
📷 有 OpenAI 的 tiktoken 和谷歌的 WordPiece 等等

4）词表大小 Vocab Size：为什么 GPT-2 中文不好

一个 Tokenizer 认识的所有 token 数量，叫做词表大小 Vocab Size。

❗ tiktoken 库中最小的词表：GPT-2 的 r50k_base 只认识 50257 个 token。因为词表太小，所以多数中文都是一个字对应一个 token，甚至有些不常见的字要好几个 token 才能表示，很少会像英文那样直接把一个单词映射成一个 token。

这样一来，中文的处理效率自然就变得很低了 —— 这也是 GPT-2 对中文支持不好的原因之一。
📷 tiktoken 库中最小的词表：1=Apple / 2=Banana / 3=Pear / 4=old / 5=est / 6=good

而对中文支持更好的 GPT-4o，不仅模型本身变大了，它的 tiktoken 词表也增大到了 20 万（o200k_base），基本覆盖了所有的中文单词，从根本上增加了中文的处理效率。

📷 GPT-4o 使用 o200k_base，词表增大到 20 万
📌 特别提醒：Token 化属于数据预处理 转化 token 的过程属于数据的预处理，这个过程本身并不是大模型的一部分。训练大模型的时候，Tokenizer 本身是固定不变的。

🤔 二、Token 的问题：一个数字表达不了"既近又远"

大模型是一个连续函数，但这个特性还没被用起来

1）大模型是一个超级复杂的连续函数

现在我们有了 Tokenizer，就可以把任何文字转化成数字，并放入大模型进行计算了。而大模型本身，则可以近似地被看成一个超级复杂的连续函数：token 就是函数的输入，而函数的输出也就是大模型的回复。

📷 输入 2 和 1，经过连续函数，输出 456
💡 关键点：连续这个特性天然决定了 如果输入的数值离得很近，那输出的数值通常也会离得很近。

还是因为算力有限，所以我们希望在有限的计算资源下，利用这个特点来增加训练的效率。

比如说：

  • 老王爱吃苹果
  • 老王爱吃 Apple
  • 老王爱吃りんご（日语"苹果"）

它们都是同一个意思，所以我们希望模型输出的内容应该也是差不多的。

"老王爱吃"都是相同的文字，所以 token 肯定也是相同的。那么如果说 苹果 / Apple / りんご 对应的 token 本身也很相近的话，根据函数的连续性，模型天生就会输出比较相似的内容。如果我们能够利用这个特点，在训练的时候就可以省下不少的算力。

2）但 token 本身只是一个数字

但是 token 本身只是一个数字，也就是一个维度。我们在设计 Tokenizer 的时候，当然可以让 苹果 / Apple / りんご 对应的 token 离得比较近。

那香蕉呢？

⚠️ 一个数字无法调和的矛盾
  • 香蕉和苹果并不是一个东西，但又都是水果、又都是中文 —— 似乎应该离中文的苹果比较近；
  • 香蕉和 Apple 既不是同一个东西，又不是同一种语言 —— 似乎应该离得又比较远；
  • 但是香蕉离 Apple 远了，离苹果也就远了。
可以看到，只是用一个数字，我们根本没有办法表达这种"既近又远"的关系。
📷 香蕉 20、苹果 21、Apple 22、りんご 23 —— 编号拉不开"既近又远"的关系

📐 三、Embedding：用一个向量描述一个词

既然一个数不行，我们就多用几个数

1）从一维编号到多维向量

那么解决方法是什么呢？既然一个数不行，我们就多用几个数呗。

于是人们也不管 token 到底是多少了，他们把 token 又做了一次转化，变成了一个多维的向量。向量中的每个数字都代表了 token 的某些特征：

第 1 个数第 2 个数第 3 个数第 4 个数…
语言形状颜色类别…
📷 既然一个数不行，那就"用多个数！"

于是：

词语言形状颜色类别
苹果1（中文）1（圆）1（红）1（水果）
りんご2（日文）111
Apple3（英文）111
香蕉1（中文）2（长）2（黄）1（水果）
📷 于是苹果可能就是"中文 + 圆的 + 红的 + 水果 = 1 1 1 1"

这样一来，我们就可以很容易地表达出 香蕉 / 苹果 / Apple 这些既近又远的关系了。

💡 定义 而这个把 token 转化成一串数字的过程，就叫做 Embedding。
📷 这个把 token 转化成一串数字的过程，就叫做 embedding

2）Embedding 的维度：d_model / n_embd

实际模型中的 embedding 维度远不止 4 个：

模型Embedding 维度
GPT-2 XL1600 个数字
DeepSeek R17168 个数字
Gemini 3 / GPT-5未公布，猜测已经上万
📌 维度越高，模型看世界的角度越细腻 1600 个维度，就是从 1600 个不同的方面去描述一个词。Embedding 中数字的多少，通常被称为 d_model 或者 n_embd。
📷 GPT-2 XL 是 1600，DeepSeek R1 更是高达 7168 个数字

3）本质区别：Tokenizer 可以手工设计，Embedding 不行

所以：Tokenizer 是把用户文字转化成数字（token），而 Embedding 是把 token 转化成向量。这两个东西的功能虽然看起来比较相似，但它们有一个本质上的不同。

🔧 Tokenizer

  • 设计时可以写程序统计单词频率
  • 甚至麻烦一点手工设计也非常可行
  • 属于数据预处理，不是模型的一部分

🧠 Embedding

  • 向量包含几千几万个维度
  • 还要为每一个 token 合理分配这些维度对应的数字
  • 这显然不是一个手工可以完成的任务
✅ 没错：Embedding 模块是训练出来的 Embedding 本身就是大语言模型的一部分。（视频中用"一串课末模型的基础架构"作示意，embedding 就是图中 Input Embedding 这一部分。）
📷 Tokenizer 可以写程序 / 手动设计；Embedding 有上万个维度、上万个 token，无法手动设计

4）既然 Embedding 是训练出来的，每个数字代表什么？

那么既然 embedding 是训练出来的，embedding 向量中每个数字代表的意义，也就不是人工设计的了。

❗ 人类暂时还解释不了
  • 每个数字的含义，人类暂时还没有办法解释；
  • 甚至就连"是一个数字代表一个特征"，还是"多个数字组合起来代表一个特征"，人类也都还没有弄清楚；
  • 训练的时候，模型会自动识别出如何划分特征，并且为每一个 token 自动分配特征对应的数字。
我们不知道这些数字背后代表的是什么，我们唯一知道的就是：这么做效果还不错。

我想，这也是 AI 的魅力之一吧。

⚙️ 四、Embedding 到底是怎么实现的

One-Hot 编码 + 一层最普通的 Linear

1）第一步：把 token 写成 One-Hot 编码

这里我们假设词表大小 Vocab Size 是 50257，而 embedding 的维度是 1600。

那我们就先把每一个 token 都写成一个长度是 50257 的向量：向量中几乎所有的数字都是 0，只有 token 对应的那个数字是 1。这种编码的方式叫做 One-Hot 编码。于是 token 本身就变成了一个向量。

📷 1（点赞）= 1 0 0 0 0 … 0；2（投币）= 0 1 0 0 0 … 0；向量中几乎所有的数字都是零

2）第二步：过一层 Linear

而 embedding 的实现，就是一个最最普通的线性变换层 Linear：

One-Hot 向量
输入 50257 维
→
Linear
线性变换层
→
Embedding
输出 1600 维
  • 它的输入是 50257 维向量，也就是经过 One-Hot 编码后的 token；
  • 它的输出是 1600 维向量，也就是 token embedding 后的结果。
📷 它的输入是 50257 维向量，输出 1600 维 embedding
⚠️ 工程实现上的差异 虽然在工程上 embedding 的实现可能并不是简单的线性层，比如说还可以通过查表或者稀疏矩阵来实现，不过这些都属于优化的范畴了 —— 它们本质上的数学原理是一样的。
📷 输出 1,600 个数字；工程上也可用查表、稀疏矩阵实现

3）最后一步：模型末尾的"逆操作"

最后一个问题：embedding 之后，原本是一个数字的 token 变成了 1600 个数字的向量 —— 模型自己理解起来是方便了，但是人类却理解不了了。

所以大多数大模型在最后，会增加另外一个线性层，这其实就相当于 embedding 层的逆操作：

① 最底部（Input Embedding）token → 向量

就是我们刚刚介绍的 token embedding，处在模型最下边的位置。

② 中间一大坨 Transformer处理的都是 embedding

Transformer 中间这一大坨东西，处理的都是 embedding 本身，最后输出的还是 embedding。

③ 最顶部的 Linear + Softmax向量 → token

最后的这个线性层，把输出的 embedding 转化回人类方便理解的 token。

💡 记住这条链路 token →（Embedding）→ 向量 →（Transformer）→ 向量 →（Linear）→ token

🔍 五、RAG Embedding 和 LLM Embedding 是一回事吗

不一样，但又有关系

1）先看区别

对 RAG 比较了解的朋友听到这里可能就要急了："老王老王，你说的这些都不对 —— 我学过 RAG，RAG 里的 embedding 明明是把一整段话转化成一个向量，不是像你这样一个 token 一个 token 转化的。"

没错，说得没错。RAG 的 embedding 和大语言模型的 embedding 确实是不一样的：

🤖 LLM Embedding

  • 把 token 中内涵的特征打散成一个向量
  • 粒度：一个词
  • 位置：模型最下边的 Input Embedding

📚 RAG Embedding

  • 把 一整段话转化成概括大意的向量
  • 粒度：一段话
  • 位置：模型最上边未转化的输出
📷 RAG Embedding 概括一段话；LLM Embedding 打散一个词

2）再看联系：RAG 用的是"未转化的输出"

但是它们二者之间其实又是有关系的。你还记得 Transformer 模型的最后一步做的是什么吗？

通过一个线性层，把模型输出的 embedding 转化回方便人类理解的 token。而这个没有经过转化的、模型输出的 embedding，它基本就是 RAG 的 embedding 了。

📷 Linear 之上是人类可以理解的 Token；Linear 之下、模型输出的 Embedding 基本就是 RAG embedding
⚠️ 特别澄清一句 并不是说我们训练一次模型，就能同时得到 token embedding 和 RAG embedding。
  • Token embedding 是训练大语言模型的一部分；
  • 而想得到 RAG embedding 则是要单独训练的；
  • 只是它们二者的模型结构大致相同。

当然了，最后大语言模型会把 embedding 转化回 token 一样，RAG embedding 的模型最后一般也还会做一些后续的处理，比如说池化（Pooling）什么的。

3）架构上的小区别：RAG 不做 mask

还有一点小区别：和大语言模型不同，RAG 的 Transformer 结构一般不会进行 mask，也就是所谓的 encoder-only 架构，或者是 BERT 模型。

对比项LLM 模型RAG 模型
AttentionMasked Multi-Head AttentionMulti-Head Attention（无 mask）
架构类型decoder-onlyencoder-only（BERT 类）
顶部结构Linear → SoftmaxPooling
输出目标下一个 token一个概括大意的向量
📷 RAG 模型：顶部是 Pooling，Attention 不做 mask —— 也就是所谓的 encoder-only 架构

4）最大的不同：训练方式

当然了，上面其实都是一些小修小补。它们二者最大的不同来自于训练方式的不同。

🤖 训练大语言模型：文字接龙

在训练大语言模型的时候，我们期望的输出是文字接龙游戏中的下一个 token。所以在训练的时候，我们提供的是文字接龙的素材：

输入：老王          →  训练模型输出：爱
输入：老王爱        →  训练模型输出：吃
输入：老王爱吃      →  训练模型输出：苹果

📚 训练 RAG Embedding：一对一对的文本片段

而在训练 RAG embedding 的时候，我们的目的就不是文字接龙了，而是概括文字的含义。所以训练的素材就变成了一对一对的文本片段。

📷 LLM 模型 vs RAG 模型 —— 训练方式不同
📷 输入"老王爱吃苹果"和另外一个意思相关的句子

正样本：让差距足够小

假如我想训练"老王爱吃苹果"的 embedding，我们就应该输入"老王爱吃苹果"本身，和另外一个和它意思相关的句子，比如说"小王爱吃香蕉"。

由于这两个句子都是描述"某人爱吃什么"的片段，所以我们在训练的时候，就应该让模型输出的 embedding 差距足够小。在这里，"小王爱吃香蕉"也被叫做正样本。

负样本：让差距足够大

而如果输入变成了"老王爱吃苹果"和"老李找到了女朋友" —— 考虑到老王既不是老李，老王也不可能找到女朋友，所以这两个文字可以说是毫无关联。所以我们在训练的时候，就应该让模型输出的 embedding 差距足够大。在这里，"老李找到了女朋友"也被叫做负样本。

📷 老王爱吃苹果 vs 老李找到了女朋友 —— 让差距足够大
✅ 这种训练方式叫做 Contrastive Learning（对比学习） 正样本拉近，负样本推远 —— 这就是 RAG embedding 能够"读懂语义"的根本原因。

🌌 六、哲学：同一套架构，不同的经历

视频最后 1 分钟的升华

为什么一个 token 编号不够？一维数字无法表达"既近又远"的关系（香蕉 vs 苹果 vs Apple）
Embedding 是什么？把 token 转化成一串数字（多维向量），每个维度代表某些特征
Embedding 可以手工设计吗？不行。几千几万个维度必须训练出来，它是大模型的一部分
Embedding 怎么实现的？token → One-Hot（50257 维）→ Linear → embedding（1600 维）
模型最后那个 Linear 干什么？Embedding 层的逆操作，把向量转回人类可读的 token
RAG embedding 与 LLM embedding 的区别？RAG：一整段话 → 概括大意的向量；LLM：单个 token → 打散特征的向量
二者的联系？模型最顶部"未经过 Linear 转化"的输出 embedding，基本就是 RAG embedding
训练方式差异？LLM 是文字接龙（预测下一个 token）；RAG 是对比学习（正样本拉近、负样本推远）
架构差异？RAG 一般不做 mask，是 encoder-only（BERT 类）；LLM 是 masked / decoder-only

术语解释

WordPieceGoogle 的分词算法，也是其 Tokenizer 库的名字
